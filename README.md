# MFB Think Tank

Flutter app for Android and iOS with Firebase Authentication (email/password, Google,
Sign in with Apple), Riverpod, go_router and Codemagic CI/CD. Developed on Linux or
Windows; iOS is built and signed on Codemagic's cloud Macs, so no Mac is needed.


## Prerequisites

- Flutter (stable) and Dart on `PATH`; `git`, `python3`.
- A JDK with `keytool` (for the upload keystore). The Android SDK / Android Studio is only
  needed to run on an Android device or emulator; release builds happen on Codemagic.
- Firebase CLI: `npm install -g firebase-tools && firebase login`.
- FlutterFire CLI: `dart pub global activate flutterfire_cli` (add `~/.pub-cache/bin` to `PATH`).
- Accounts: Firebase/Google Cloud, Google Play Console ($25 once), Apple Developer Program
  ($99/year), Codemagic.

## Quickstart

```bash
scripts/configure_firebase.sh <firebase-project-id>   # 1. connect Firebase (docs/FIREBASE_SETUP.md)
scripts/run.sh                                        # 2. run on a device/emulator
scripts/create_upload_keystore.sh                     # 3. Android release key (once per app)
```

Until step 1 is done the app starts with a screen explaining how to configure Firebase.
Always pass the runtime config when running or building by hand:

```bash
flutter run --dart-define-from-file=config/app_config.json
```

Then set up delivery: [Codemagic](docs/CODEMAGIC.md), [iOS without a Mac](docs/IOS_WITHOUT_MAC.md),
and before going live the [release checklist](docs/RELEASE_CHECKLIST.md).

## Project structure

```
lib/
  main.dart                 Firebase init, ProviderScope
  firebase_options.dart     generated by flutterfire (placeholder until configured)
  app/                      MaterialApp.router, go_router config + auth redirects, theme
  core/config/              AppConfig: values from config/app_config.json
  features/
    auth/
      data/                 AuthRepository (FirebaseAuth), Google + Apple gateways, failures
      application/          Riverpod providers (auth state, repository, platform)
      presentation/         sign-in, sign-up, forgot-password, splash screens and widgets
    home/                   signed-in landing page
    profile/                profile, sign-out, account deletion
test/                       unit + widget tests (firebase_auth_mocks, mocktail)
config/app_config.json      non-secret build-time config (Google client ids)
scripts/                    project tooling (see below)
docs/                       setup guides
codemagic.yaml              CI/CD workflows
```

New features go in `lib/features/<feature>/{data,application,presentation}`.

### Scripts

| Script | Purpose |
| --- | --- |
| `scripts/configure_firebase.sh <project-id>` | `flutterfire configure` for Android + iOS, registers SHA fingerprints, downloads `google-services.json` / `GoogleService-Info.plist`, patches `Info.plist` and `config/app_config.json`. Re-runnable. |
| `scripts/create_upload_keystore.sh` | Creates the Android upload keystore + `android/key.properties` (gitignored) and prints its fingerprints. |
| `scripts/run.sh [flutter run args]` | `flutter run` with `--dart-define-from-file=config/app_config.json`. |

## How authentication works

- **Firebase Auth** is the single source of truth. `authStateChanges()` is exposed as a
  Riverpod provider; go_router's redirect sends signed-out users to `/sign-in` and
  signed-in users away from auth screens, restoring deep links after sign-in.
- **Email/password**: sign-up, sign-in, password reset, email-verification banner.
- **Google** (`google_sign_in` 7): the native Google flow returns an ID token that is
  exchanged for a Firebase credential. Android needs `GOOGLE_SERVER_CLIENT_ID` (the
  Firebase *Web client* id) and registered SHA fingerprints; iOS needs
  `GOOGLE_IOS_CLIENT_ID` plus the reversed client id URL scheme in `Info.plist`. The button
  is hidden with a hint when the id for the current platform is missing.
- **Sign in with Apple** (iOS only, hidden on Android): native Apple flow with a hashed
  nonce, exchanged for a Firebase `apple.com` credential. Requires the
  `Runner.entitlements` capability (already wired) and the App ID capability in the
  Apple Developer portal.
- **Account deletion** (store requirement) re-authenticates as needed, revokes Apple tokens,
  disconnects Google and deletes the Firebase user. Delete your own backend data too.

### Configuration and what is committed

| File | Committed | Notes |
| --- | --- | --- |
| `lib/firebase_options.dart`, `firebase.json` | yes | generated by `flutterfire configure` |
| `android/app/google-services.json`, `ios/Runner/GoogleService-Info.plist` | yes | identify the Firebase project, not secrets |
| `config/app_config.json` | yes | public OAuth client ids, read with `String.fromEnvironment` |
| `android/key.properties`, `*.jks` | **never** | upload key; back it up and upload to Codemagic |

Secrets for CI (service account JSON, certificate key, App Store Connect API key) live only
in Codemagic.

## CI/CD

[`codemagic.yaml`](codemagic.yaml) has `ci` (analyze + test on pushes/PRs to `main`),
`android-release` (AAB → Play internal track), `ios-release` (IPA → TestFlight) and a manual
`release-all`. Pushing a tag `vX.Y.Z` releases to both stores; build numbers are derived from
the stores automatically. Setup: [docs/CODEMAGIC.md](docs/CODEMAGIC.md).

## Development

```bash
flutter analyze
flutter test --dart-define-from-file=config/app_config.json
```

Most work happens on an Android emulator/device or in tests. iOS-specific behaviour (Apple
sign-in, Google URL scheme) is verified on a real iPhone through TestFlight
([docs/IOS_WITHOUT_MAC.md](docs/IOS_WITHOUT_MAC.md)).
